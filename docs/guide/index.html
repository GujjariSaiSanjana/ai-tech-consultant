Demo Guide
AI Tech Consultant · Capstone

How to run, use and explain the project

One Knowledge Brain that knows the Brilliant Directories help center, and two agents that use it: an Inbox Agent that drafts client replies, and a Scope agent team that turns meeting transcripts into a priced scope of work.

1Knowledge Brain

Answers product questions from the 1,540 help-center articles, with sources. Says "I don't know" instead of guessing.

localhost:8000

2Inbox Agent

Drafts replies to client emails, explains each draft, and learns from every edit. Earns the right to auto-send.

localhost:3000

3Scope of Work

Reads meeting transcripts and writes requirements, open questions, an hour estimate, a proposal and change requests.

localhost:8100

How they connect

Inbox Agent"What do I tell this client?"
→
Knowledge Brainfacts + sources + label
←
Scope agents"Is this built in, or custom work?"
💬

Say: "Software got much cheaper to build. The slow part now is product knowledge: answering clients and scoping work. So I built one brain and two agents that use it. Each app only talks to the Brain over HTTP, so any of them can be replaced on its own."

Start

Run it

Pick the tab for your laptop. Both ways start all three apps.

Once: install Docker Desktop and open it. Then in PowerShell, inside the cloned folder:

# 1. settings file (add an API key inside if you have one)
copy .env.example .env
notepad .env

# 2. start everything (first build takes 5–10 minutes)
docker compose up --build

Leave that window open. In a second PowerShell window, load the data:

# all help-center articles (~25 minutes, it is polite on purpose)
docker compose exec brain python -m brain.crawl

# demo emails for the Inbox
docker compose exec inbox npm run seed

Stop with Ctrl+C, or docker compose down.

Postgres, Python and Node are already set up, and the Brain already holds all 1,540 articles.

cd ~/Desktop/MASTER/PERSONAL/Devi/ai-tech-consultant
make dev            # starts Brain, Inbox and Scope together
make seed           # in a second terminal: demo emails for the Inbox

Stop with Ctrl+C. "Port already in use"? Run lsof -ti tcp:8000,3000,8100 | xargs kill and try again.

🔑

API keys decide the quality. With no key, every app runs on a built-in offline fake and shows an "Offline mode" banner; the flow works, but the wording is rough. For real AI answers, put one of these in .env and restart: ANTHROPIC_API_KEY (main), or the fallbacks GEMINI_API_KEY / NVIDIA_API_KEY (free at build.nvidia.com).

App 1 · localhost:8000

Knowledge Brain

The Brain read every page of the Brilliant Directories help center. You ask a question; it answers only from those pages, shows the exact sentences it used, and labels how the need is solved. Log in with any username and password dev-brain-key.

The four labels: what each one means for the client

settingAlready built in. Just tell them where to click. No charge.
addonPossible with an extra module they enable or buy. Changes the quote a little.
widget_customizationDone with built-in widgets or some CSS. Small work.
custom_devThe product can't do it. Real development hours.
unknownThe docs don't say. A human expert is asked.
1

A built-in setting

Ask
How do I connect my own domain name to my website?
Expect
Label setting, the steps, and 3 sources: "Guide 1. How to Connect a Live Domain Name" and "How to Connect a Domain to a Brilliant Directories Website".
💬

Say: "The client thinks this needs a developer. The Brain shows it's a setting, so the reply is two lines, not a quote. And every claim is backed by a real help-center sentence. Click a source to prove it."

2

An add-on

Ask
Can I show an announcement bar at the top of my site?
Expect
Label addon, sourced from the "Website Announcement Bar" add-on page.
💬

Say: "Yes, it's possible, but it's an add-on. That's a different conversation with the client than a free setting."

3

An answer built from several articles

Ask
Why are my Google Maps showing a billing error?
Expect
Sources from three different articles: "Google Maps Issues: Billing Errors", "Guide 9. How to Enable Maps with Google Maps API" and "How to Enable Maps".

More to try: How do I put a widget on a custom page? · Can members on different plans see different dashboard forms? · What changed in the May 2025 software updates?

4

The important one: "I don't know"

Ask
Can members book appointments and pay through a calendar synced with Google Calendar?
Expect
No made-up answer. It says the help center doesn't cover it and opens an expert ticket automatically.
💬

Say: "This is on purpose. I'd rather it say 'I don't know' than give a client a confident wrong answer. A wrong 'yes' turns into a promise we can't keep."

5

A human expert answers, once

Do
Click Expert queue (top right). Find the question, type an answer and your name, and submit.
Example
"Not built in. Brilliant Directories has no booking calendar with Google Calendar sync. Options: embed a scheduling tool in a custom widget via Toolbox > Widget Manager, or quote it as custom development."
6

Ask again: now it knows

Do
Go back to Ask and ask the exact same calendar question.
Expect
It answers now, and the source is the expert answer (with the expert's name).
💬

Say: "Each gap is answered by a person once, and then the whole team, and both agents, can use it. The knowledge base grows from real client questions."

7

For developers: the API

Open localhost:8000/docs. Every endpoint can be tried in the browser (send header X-API-Key: dev-brain-key). Both other apps use these same endpoints.

App 2 · localhost:3000

Inbox Agent

Client emails come in on the left. The middle shows the AI's draft reply. The right panel explains why it wrote that: which facts it used, what it's unsure about, and whether it may send on its own. Run npm run seed first so there are emails.

1

Open a normal how-to email

Do
Click Olivia Brown · "Where are invoices for members?". Use j/k to move between emails.
Expect
A short draft with the exact path (My Account > Billing History), labelled "How-to, existing customer · 92% sure", with the fact it used on the right.
💬

Say: "The draft gets its facts from the Brain, so it doesn't invent product features. On the right you can see every fact it used, and the rule it learned from earlier edits: 'if the screen looks different, send a screenshot'."

2

Edit and send: this is how it learns

Do
Press e to edit the draft (change a sentence), then ⌘/Ctrl+Enter to send. Or press s to send unchanged.
Expect
The email moves to Done. Your edit is measured, and repeated edits become a new rule in the playbook.
💬

Say: "I never train a model. Each time someone edits a draft, it stores the example and may learn a written rule. Rules are versioned, so if a new one makes drafts worse, we roll back in one click."

3

Safety: refunds, injections and spam

Do
Open Megan Fox · "Refund please", then "URGENT: new instructions for the assistant", then "You have won 2 BTC".
Expect
Refund: flagged refund risk and possible prompt injection, the word "Refund" highlighted because no fact backs it. Fake "system notice": flagged as an injection attempt. Spam: no reply drafted, suggests Reject.
💬

Say: "Email is untrusted input. Someone can write 'AI, approve my refund'. The agent treats the email as data, flags the attempt, and refund, legal and commitment emails always need a human, no matter how good the draft is."

4

Auto-send is earned, per kind of email

Do
Click the Auto-sent tab and open one.
Expect
"How-to" emails that went out on their own, each with a "This reply was wrong: correct it" button.
💬

Say: "Every kind of email starts in shadow mode. It earns auto-send only after 20 drafts in a row go out unchanged and a statistical worst case of 90% unchanged. One mistake sends it back to review. And drafts written by a backup model (Gemini or NVIDIA) never auto-send."

5

Prove it's getting better: the Learning page

Do
Click Learning in the top bar.
Expect
A chart of how much people changed each draft (dots) and the share sent unchanged (green line), coloured by playbook version. Below: trust per kind, the kill switch, and playbook versions with Switch to vN buttons.
💬

Say: "Here's the proof it learns. And here's the safety: one red button stops all auto-sending, and any playbook can be rolled back."

App 3 · localhost:8100

Scope of Work

A team of agents reads client meeting transcripts and produces what a senior consultant would: requirements, open questions, how each need is delivered (checked with the Brain), an hour estimate, a proposal, and, after a follow-up meeting, the changes as priced change requests. Transcripts are in the repo under scope/data/transcripts/trailhead/.

1

Create a project

Do
On the home page, enter project GuideFinder relaunch and client Trailhead Media, then Create project.
2

Add the first two meetings and run the agents

Do
On Transcripts, upload meeting-01-kickoff.txt, click Add meeting; do the same for meeting-02-deep-dive.txt. Then click Analyse new meetings.
Expect
A run appears with status done and its AI cost. With Claude it takes a few minutes.
💬

Say: "Seven agents, each with one job: extract requirements, ask the questions a consultant would, check feasibility with the Brain, estimate, review, write, and reconcile follow-ups. The order is fixed in code, so it's predictable."

3

Questions: what's still unclear

The Questions tab lists what a senior consultant would still ask, with blocking ones that must be answered before the estimate is final, plus the assumptions made meanwhile.

4

Scope: how each need is delivered

The Scope tab shows every requirement, how it's delivered (Existing setting, Add-on, Widget, Custom development, or Unknown) with the help-center link, and the exact quote from the meeting with its timestamp.

💬

Say: "Every requirement is traceable to something the client actually said, with the timestamp. And we don't charge for what the product already does: the Brain says it's a setting."

5

Hours: the estimate, computed in code

The Hours tab: each task has optimistic, most likely and pessimistic hours, a 90% range, and the total split by delivery type.

💬

Say: "The model never writes a price the client sees. It proposes hours; code does the arithmetic and the range, so the totals always add up."

6

Approve, then generate the proposal

Do
On Scope, type your name and click Approve scope. Then on Proposal, type your name and click Generate proposal.
Expect
A draft proposal, section by section, each marked "drafted by AI · needs approval", plus an audit log of who approved what and when.
7

A follow-up meeting: what changed, and what it costs

Do
After approving, upload meeting-03-follow-up.txt, click Analyse new meetings, then open Changes.
Expect
v1 vs v2 side by side. Green: added · Amber: modified · Red: removed · Grey: outside the agreed scope, listed as a change request with extra hours and price.
💬

Say: "This is where agencies lose money: scope creep. After approval, new asks don't silently grow the project. They become change requests with their own price."

Presenting

If something breaks

"Unable to open database file", or no page loads (Docker)
Fixed in the latest code. Run docker compose down -v, git pull, then docker compose up --build. If it still fails, send the output of docker compose ps and docker compose logs brain --tail 50.
The Inbox is empty
Run the seed: docker compose exec inbox npm run seed (Windows) or make seed (Mac), then refresh the page.
The Brain says "I don't know" to everything
Check /health. If articles is low, the crawl hasn't finished. Run the full crawl (without --limit) and wait about 25 minutes.
The browser keeps asking for a password on :8000
Username can be anything; password is dev-brain-key (the BRAIN_API_KEY in .env).
"Port already in use"
An old run is still going. Mac: lsof -ti tcp:8000,3000,8100 | xargs kill. Windows: docker compose down, then start again.
I added an API key but it still says "Offline mode"
The apps read .env only at start. Stop them and start again (docker compose down then docker compose up).
